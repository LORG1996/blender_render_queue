Додавання вибору камери — це абсолютний must-have для архітектурної візуалізації, оскільки в одному файлі зазвичай зберігається десяток ракурсів (різні плани кімнати, екстер'єр, деталі), і рендерити їх усі підряд або вручну перемикати в блендері — справжній біль.

Оновлюємо наше ТЗ. Я додав пункт про вибір камери в розділ параметрів задачі та в структуру парсингу.

Технічне завдання (ТЗ): Blender Autonomous Batch Renderer
1. Загальна інформація про проєкт

    Назва проєкту: Blender Batch Queue Manager (або робоча назва за вибором).

    Призначення: Десктопний автономний додаток на Python для керування чергою рендерингу проєктів Blender (.blend) у фоновому режимі з можливістю тонкого настроювання кожної задачі.

    ЦА: 3D-художники, фрилансери, невеликі студії, яким потрібен легкий і гнучкий менеджер рендеру без громіздких пайплайнів.

2. Технологічний стек

    Мова програмування: Python 3.10+

    Графічний інтерфейс (GUI): PySide6 (або PyQt6) — забезпечення нативного вигляду, підтримки темної теми та зручних таблиць/списків (QTableWidget / QListView).

    Бекенд рендеру: subprocess (запуск виконуваного файлу Blender у фоновому режимі через аргументи -b / background).

    Прев'ю та обробка зображень: Pillow або OpenCV для швидкого кешування та відображення мініатюр.

3. Основні функціональні вимоги
3.1. Керування чергою завдань (Render Queue)

    Додавання нових завдань до черги (через вибір .blend файлу або перетягування drag-and-drop).

    Можливість дублювати, видаляти та змінювати порядок завдань у черзі (Drag & Drop або кнопки керування "Вгору/Вниз").

    Статуси завдань: У черзі (Queued), Ренндериться (Rendering), Завершено (Completed), Помилка (Failed), Скасовано (Canceled).

    Кнопки керування процесом: Start Queue, Pause / Skip, Stop.

3.2. Гнучкі налаштування для кожної задачі (Task Parameters)

Для кожного доданого файлу у черзі користувач може налаштувати:

    Шлях до файлу Blender (.blend).

    Вибір сцени (динамічний парсинг доступних сцен із .blend файлу при додаванні).

    Вибір активної камери:

        Динамічне зчитування списку всіх камер (bpy.data.objects, якщо тип об'єкта CAMERA) у вибраній сцені. Можливість обрати конкретну камеру для рендеру конкретної задачі (перевизначення активної камери сцени через мікроскрипт).

    Вибір активного дерева композитора (Compositor Tree):

        Зчитування наявних дерев нод композитингу та вибір потрібного стилю постобробки для завдання.

    Діапазон кадрів (Start Frame, End Frame, Step). За замовчуванням підтягуються налаштування зі сцени, але їх можна перевизначити.

    Шлях збереження результату (Output Directory) та формат вихідних файлів (PNG, EXR, JPEG тощо).

    Пресети рендеру (вибір двигуна — Cycles/Eevee, кількість семплів, роздільна здатність тощо).

3.3. Візуальне прев'ю (Preview & Intuitive UX)

    При додаванні .blend файлу програма за допомогою невеликого блендер-скрипта в командному рядку швидко генерує мініатюру або рендерить перший кадр у низькій роздільній здатності (з урахуванням вибраної камери).

    Відображення картки завдання в інтерфейсі з іконкою-прев'ю, назвою файлу, вибраною сценою, камерою, композитором та прогрес-баром.

    Індикатор загального прогресу черги та поточного кадру, що рендериться.

3.4. Логування та консоль

    Окреме вікно або вкладка з виводом логів рендеру в реальному часі (stdout/stderr від процесу Blender).

    Автоматичне збереження логів у текстовий файл для кожної сесії рендеру для зручної діагностики помилок.

4. Архітектура та структура майбутнього коду

Проєкт має бути розділений на модулі:

    main.py — точка входу, ініціалізація додатку PySide6.

    ui/ — файли інтерфейсу (головне вікно, панелі налаштувань задач).

    core/ — логіка черги рендеру (QueueManager), взаємодія з Blender CLI (BlenderProcess).

    utils/ — допоміжні функції для парсингу .blend (зчитування сцен, камер та композиторів через bpy в headless режимі) та генерації мікроскриптів.
